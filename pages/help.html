How to use PhyloFlask

PhyloFlask turns a BLAST search into interactive phylogenetic-profiling visualisations: it builds species × domain presence/absence matrices and, from them, a species tree, domain clusters and heatmaps.

The pipeline at a glance

1. BLAST file 2. Correlation / feature matrix 3. Tree / Clusters / Heatmap

Run BLAST Analysis first — the correlation matrix it produces is the input for the tree builder, all-vs-all and heatmaps.

1 · BLAST Analysis

What it is
Parses a BLAST tabular file and aggregates hits into a matrix.
Input
A BLAST -outfmt 6 file (.blastp/.tsv/.txt). Query = domain, Subject = species.
You see
An upload drop-zone, an analysis-type selector, and a download link.
You can do
Choose Correlation matrix (presence/absence counts) or Feature matrix (per-cell JSON: %identity, bitscore, e-value, hits). Download the CSV.
Why
A hit only counts as “present” when its E-value ≤ 1e-5, so profiles stay meaningful for downstream comparison.

2 · Tree builder

What it is
Builds a Neighbour-Joining species tree from domain profiles.
Input
The correlation matrix CSV from step 1.
You see
A workflow stepper, an upload zone, a progress bar, and a download link for the resulting .nw file.
You can do
Upload & start construction; download the Newick tree, then open it in the Tree viewer.
Why
Distances are the Jaccard distance between species’ presence/absence profiles — species that share domain content sit close together.

3 · All-vs-all (domain clustering)

What it is
Clusters domains that share a phylogenetic profile (Markov Clustering).
Input
The correlation matrix CSV.
You see
An interactive network (nodes = domains, coloured by cluster, sized by degree), a result note with cluster count & modularity, and a linked co-cluster matrix.
You can do
Drag/zoom; hover for a tooltip; click a node to isolate its cluster; move the min-similarity slider to prune weak edges; switch layout; click a heatmap cell to jump to that domain in the network.
Why
Edges connect domains with Jaccard similarity ≥ threshold; co-occurring domains are candidate functional modules. Modularity ≈ 0 means the data has little structure (see FAQ).

4 · Tree viewer

What it is
An interactive radial viewer for any Newick tree.
Input
A .nw file (e.g. from the Tree builder).
You see
A radial tree with leaves coloured by genus.
You can do
Click nodes to collapse/expand; use expand-to-depth, expand-all, collapse; search a species to highlight its path to the root; zoom/pan; hover for descendant counts.
Why
Collapsing is essential for large trees (hundreds of leaves); colouring by genus reveals whether related species group together.

5 · Heatmaps

What it is
Three views of a matrix CSV: feature heatmap, correlation heatmap, dendrograms.
Input
A feature/correlation matrix CSV (processed in your browser).
You see
A species × domain heatmap with a colour scale.
You can do
Pick a feature, filter by min hits, toggle log scale and ordering, box-zoom, download a PNG, and click a cell to see its full feature vector.
Why
Log scaling and ordering make broad patterns of presence/abundance visible across many domains at once.

Tips

  • Local URL is http://127.0.0.1:8000 (port 5000 is taken by AirPlay on macOS).
  • Most tools accept the correlation matrix from BLAST Analysis — run that first.
  • Large trees take time to build (Neighbour-Joining is O(n³)); the progress bar keeps you posted.
  • See the FAQ for the science behind each step.
